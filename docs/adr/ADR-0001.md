# ADR-0001: Naming and trademark-safe identity

Status: **Accepted** — 2026-07-25
Amended 2026-07-25 (Prompt 1a) — free-tier absolutism replaced by a
"free distribution is complete standalone; a separate commercial distribution
may exist only via a superseding ADR" rule. Immutable identity rules unchanged.

## Context

A predecessor plugin in this exact niche (per-product custom WooCommerce
emails) was removed from WordPress.org because its public identity led with
the "Woo" trademark. WordPress.org and the WooCommerce trademark policy
prohibit third-party plugins from leading their name, slug, or marketing with
"Woo"/"WooCommerce" as the brand. A plugin that builds its identity around a
trademark it does not own carries a permanent, existential distribution risk:
the listing can be taken down at any time regardless of code quality, and all
install/rank equity is lost with it.

This plugin extends WooCommerce and must say so factually ("for WooCommerce"
as a descriptor is permitted), but its *identity* — the thing users search
for, the slug in the URL, the PHP namespace, the database table prefix — must
be owned by us and must not depend on anyone else's mark.

## Decision

The identity is **brand-first and immutable**, exactly as fixed in the project
identity block:

- **Plugin name:** Extonify Custom Emails Per Product for WooCommerce
  (brand "Extonify" leads; "for WooCommerce" is a trailing factual descriptor,
  never the lead token).
- **Slug + text domain:** `extonify-custom-emails-per-product`.
- **PHP namespace:** `Extonify\WCEP`.
- **DB table prefix:** `{$wpdb->prefix}extonify_wcep_`.

The plugin is **free**. There are no Pro labels, upsells, feature locks,
"upgrade" nags, or teaser-disabled features anywhere — not in the admin UI, not
in the code, and not in `readme.txt`. Every advertised capability is available
in the distributed plugin.

All code targets **PHP 8.0–8.4**. No PHP 8.1+ syntax (no enums, no `readonly`
properties, no `never` return type, no first-class callable syntax, no
`new` in initializers) appears anywhere the plugin can reach at runtime.

This identity is **immutable**: none of the name, slug, text domain, namespace,
or table prefix may be changed, abbreviated, or re-led by a trademark in any
future prompt or release without a superseding ADR.

## Consequences

- The slug, text domain, `Text Domain:` header, `.pot` filename, namespace
  root, and table prefix are all derived from a single owned brand and never
  need to change to satisfy a trademark takedown.
- Marketing and `readme.txt` may describe WooCommerce compatibility factually
  but must never present "Woo"/"WooCommerce" as the product's own brand. Named
  third-party compatibility claims are separately gated by
  [ADR-0006](ADR-0006.md).
- The distributed WordPress.org plugin is **fully free and complete**: no Pro
  labels, upsells, license checks, upgrade notices, locked controls, or
  teaser-disabled features, and **no code path branches on a licence tier**.
  A future commercial product may exist as a **separate distribution**,
  introduced only by a **superseding ADR**; the free plugin must remain complete
  and fully functional standalone regardless of whether such a product exists.
- The PHP 8.0 floor constrains syntax in every file the autoloader can load.
  The main plugin bootstrap additionally stays parseable by older PHP so a
  failed requirement check degrades to an admin notice rather than a parse
  fatal (house-style, mirrored from the sibling Address Book project).
- Any task that appears to require re-leading the identity with a trademark must
  be escalated rather than silently implemented. Introducing a paid tier is not
  forbidden outright, but it may only arrive as a separate distribution under a
  superseding ADR and must never degrade the free plugin.

## Amendment history

- **2026-07-25 (Prompt 1a):** Replaced the free-tier absolutism. Removed
  "New features ship to everyone or not at all" and "adding a paid tier is out
  of scope". The distributed WordPress.org plugin remains fully free and
  complete standalone; a commercial product, if it ever exists, is a **separate
  distribution** introduced only by a superseding ADR. Why: the original wording
  over-constrained the business model (forbidding any future paid product) while
  the real, durable requirement is only that the *free* distribution stay
  complete and licence-check-free. Immutable identity rules are unchanged.
